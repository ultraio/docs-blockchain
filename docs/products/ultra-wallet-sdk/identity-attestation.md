# Identity Attestation

An **identity attestation** is a short-lived statement, signed by the wallet, that says: _"key X, which controls account Y on chain Z, is connecting to origin O."_ It comes with the `connect()` result, so there is **no extra signing prompt**. Your backend can verify it and start a session without a separate [signed-nonce login](./connecting.md#login-with-a-signed-nonce).

::: info Requirements
-   **Ultra Wallet Browser Extension 2.2.13 or later.** The Web Wallet does not issue attestations.
-   The `attestation` result type needs **SDK 0.4.0+**, and the `requireAttestation` option needs **SDK 0.5.0+**. The SDK passes both through unchanged, so older SDK versions also work at runtime if you cast the types.
:::

## Getting an attestation

```ts
const { data } = await wallet.connect({ requireAttestation: true });

if (data.attestation) {
    await fetch('/auth/attestation', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data.attestation),
    });
} else {
    // Web Wallet or an older extension: fall back to a signed-nonce login
}
```

**Consent.** Approving a connection in the extension counts as consent to attestations. The approval screen tells the user about it. After that, every `connect()` from your origin, including silent reconnects, includes a fresh attestation. Sites the user trusted **before** the extension supported attestations have not consented yet. For those sites, `requireAttestation: true` shows the connection prompt **once** to collect consent, instead of silently returning a result without an attestation. Without the flag, such a site gets `attestation: undefined`.

**Account changes.** When the user switches accounts, the [`accountChanged`](./events.md#accountchanged) event includes a new attestation for the new account. Send it to your backend to switch the session without another connection.

## Structure

```ts
interface ConnectAttestation {
    payload: AttestationPayload;
    signature: string; // "SIG_K1_…"
}

interface AttestationPayload {
    v: 1;
    pubkey: string; //     the signing key, e.g. "EOS7HUZ…"
    account: string; //    the selected account
    permission: string; // the permission the key belongs to (usually "active")
    origin: string; //     your dApp's origin, as determined by the wallet (not by your page)
    chainId: string; //    the network the wallet is on
    iat: number; //        issued at, unix seconds
    exp: number; //        expires at, unix seconds (default iat + 24h)
    nonce: string; //      32 random bytes, hex; generated by the wallet
    signableAccounts?: { account: string; permissions: string[] }[]; // every account the wallet can sign for
}
```

The `origin` field is filled in by the extension from the tab's real origin, so a malicious site cannot get an attestation made out to your origin.

## How it is signed

1. The wallet builds the **canonical JSON** of `payload`: `JSON.stringify` with the object keys sorted alphabetically **at every nesting level**. Array order is kept, and there is no whitespace.
2. It signs the UTF-8 bytes of that string with the key in `payload.pubkey`, as a K1 signature over their SHA-256 hash. This is the same scheme as [`signMessage()`](./signing.md#verifying-a-message-signature).

## Verifying on your backend

The SDK does **not** verify attestations. Your backend must check everything below before it trusts one:

```ts
// Node.js, using @wharfkit/antelope
import { APIClient, Bytes, PublicKey, Signature } from '@wharfkit/antelope';

const EXPECTED_ORIGIN = 'https://example.com';
const EXPECTED_CHAIN_ID = 'a9c481dfbc7d9506dc7e87e9a137c931b0a9303f64fd7a1d08b8230133920097';
const client = new APIClient({ url: 'https://api.mainnet.ultra.io' });

function canonicalize(value: unknown): unknown {
    if (Array.isArray(value)) return value.map(canonicalize);
    if (value && typeof value === 'object') {
        return Object.fromEntries(
            Object.keys(value as object)
                .sort()
                .map((k) => [k, canonicalize((value as Record<string, unknown>)[k])]),
        );
    }
    return value;
}

export async function verifyAttestation({ payload, signature }: { payload: any; signature: string }) {
    // 1. Format, audience, network and freshness
    if (payload.v !== 1) throw new Error('unsupported version');
    if (payload.origin !== EXPECTED_ORIGIN) throw new Error('wrong origin');
    if (payload.chainId !== EXPECTED_CHAIN_ID) throw new Error('wrong chain');
    const now = Math.floor(Date.now() / 1000);
    if (now < payload.iat - 60 || now >= payload.exp) throw new Error('expired or not yet valid');

    // 2. The signature was made by payload.pubkey over the canonical payload
    const message = Bytes.from(JSON.stringify(canonicalize(payload)), 'utf8');
    const recovered = Signature.from(signature).recoverMessage(message);
    if (!recovered.equals(PublicKey.from(payload.pubkey))) throw new Error('bad signature');

    // 3. On chain, that key really controls account@permission
    const { accounts } = await client.v1.chain.get_accounts_by_authorizers({ keys: [recovered] });
    const ok = accounts.some(
        (a) => a.account_name.equals(payload.account) && a.permission_name.equals(payload.permission),
    );
    if (!ok) throw new Error('key is not authorized for this account');

    // 4. Replay protection: reject a nonce you have already accepted (store it until `exp`)
    await rememberNonceOrThrow(payload.nonce, payload.exp);

    return { account: payload.account, permission: payload.permission };
}
```

::: tip API node
The lookup needs an API node that supports `get_accounts_by_authorizers`, such as `https://api.mainnet.ultra.io` on mainnet or `https://api.testnet.ultra.eossweden.org` on testnet. Not every public node supports it.
:::

::: warning Do not skip the on-chain check
The signature proves only that someone holds `pubkey`. Step 3 proves that the key controls the account **right now**. Keys can be rotated or removed from an account at any time.
:::

`signableAccounts` lists every account the wallet can sign for, so your backend can offer an account picker without trusting a list from the frontend. The attestation signature covers it, but to rely on a specific entry, confirm it on chain the same way as step 3.

## Lifetime

Attestations are valid for **24 hours** by default. The extension also accepts a `ttlSeconds` connection parameter, between 60 seconds and 7 days. It is not in the SDK's types yet:

```ts
await wallet.connect({ requireAttestation: true, ttlSeconds: 3600 } as any);
```

Use the attestation to **start** a session, then issue your own session token. Don't store the attestation as a long-lived credential.
